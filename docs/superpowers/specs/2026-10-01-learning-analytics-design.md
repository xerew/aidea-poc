# Detailed Learning Analytics — Design

Date: 2026-10-01 · Status: approved in conversation, awaiting spec review

## Purpose

Give AIDEA trustworthy, per-person learning data, in priority order:

1. **Research (B):** complete raw data per learner per item, exported to Excel for statistical analysis.
2. **Improving content (A):** where learners spend time, struggle or stop.
3. **Following learners (C):** who is stuck or inactive, so course staff can reach out.

### Decisions taken

| Topic | Decision |
|---|---|
| Who sees per-person data | As today: anyone who can see a course's analytics (authors/co-editors their courses; AIDEA partners and admins all) sees **named** data, on the web and in Excel. |
| Time measure | Record **both** *active* time (page visible and input in the last 60 s, or a video playing) and *on-screen* time (page visible). Active is the headline figure. |
| Extra signals | Video behaviour, quiz detail (time per question), PDF & image use, context (language, device, local time). |
| Excel layout | Long-format sheets for analysis **plus** a wide Overview sheet. |
| Collection approach | Sessions + events stored in our own database (not Matomo, not a nightly-aggregated raw stream). |
| Status flags | inactive = no activity 14+ days; stuck = 3+ visits to one resource without finishing it, or a failed quiz; on track otherwise; completed when the course is done. |

### Why today's data is not enough

`ResourceProgress.time_spent_seconds` = time from the learner's latest opening of the activity until that resource was marked done. It is cumulative across the resources of an activity page, includes idle time, and is written once (revisits unmeasured). Activity opens (`LessonSession`) are recorded but not their end. Module time is not stored. This design replaces timing with measured visits; completion, quiz and assignment data are kept as they are.

## Data model

### `ResourceVisit` — one row per learner, per resource, per page visit

| Field | Notes |
|---|---|
| `user` FK, `resource` FK | |
| `activity` FK, `module` FK, `course` FK | denormalised for fast per-course queries |
| `visit_key` (UUID, unique with `user`) | generated by the browser per resource per page visit; makes heartbeats idempotent |
| `started_at`, `last_seen_at` | |
| `active_seconds`, `visible_seconds` | accumulated from heartbeats; `active ≤ visible` enforced |
| `completed_during` (bool) | the resource was completed in this visit |
| `language` (≤8), `device` (`desktop`/`tablet`/`mobile`), `local_hour` (0–23), `tz_offset_minutes` | context; no IP, no precise location |
| `media_progress` (JSON) | videos: `{covered_pct, furthest_s, duration_s}` for this visit |

Indexes: `(course, user)`, `(resource, user)`, `(user, last_seen_at)`.

### `LearningEvent` — one row per discrete moment

| Field | Notes |
|---|---|
| `user` FK, `resource` FK, `visit` FK (nullable), `course` FK | |
| `event_type` | `video_play`, `video_pause`, `video_seek`, `video_ended`, `pdf_open`, `pdf_download`, `image_open`, `quiz_answer` |
| `occurred_at` | |
| `data` (JSON) | e.g. `{position}`, `{from, to}`, `{question_index, selected, correct, seconds_on_question}` |

Module and activity times are **derived** (sums over resource visits), never stored, so they always agree.

### Switch

`LearnerActivityConfig.tracking_enabled` (default `True`), editable in Django admin. When off, the server ignores tracking messages and reports the setting to the page, which stops sending.

### Unchanged

`ResourceProgress` (completion, quiz score/answers, engagement data), `AssignmentSubmission`, `Enrollment`. `ResourceProgress.time_spent_seconds` stays in the database but analytics stop using it.

## Collection (learner activity page)

- A tracker on the activity page (the only place content is consumed) decides which resource time belongs to, because an activity shows all its resources on one scrolling page: **a playing video**, else **the resource being interacted with** (quiz answering, assignment typing), else **the resource occupying most of the viewport**.
- It sends one batched message to `POST /api/tracking/` every **30 s**, and immediately on tab hide / close (`fetch` with `keepalive`, which carries the auth header):
  - per resource used since the last message: `visit_key`, `resource_id`, `active_delta`, `visible_delta`, `media` (videos), `completed` flag when relevant;
  - events since the last message;
  - context once per visit (language, device, local hour, tz offset).
- **Active** = page visible and (scroll, key, click, touch or pointer move in the last 60 s, or a video playing). **On-screen** = page visible.
- **Video:** `<video>` files via media events; YouTube via the IFrame Player API (`enablejsapi=1`); Vimeo via the Player SDK. Coverage = union of played ranges ÷ duration.
- **PDF / image:** "opened full-size" and "downloaded" events and on-screen time; pages read inside a PDF are not observable.
- **Quiz:** for each answered question, seconds since the question was shown.
- **Failure handling:** unsent deltas stay in memory and are resent with the next message; time from a tab closed while offline may be lost.

### Server safeguards

- Per message and per visit: `active_delta`, `visible_delta` capped at 35 s; `active ≤ visible` after applying.
- Only resources in courses the user is enrolled in; others ignored.
- Rate-limited per user. Unknown `visit_key` creates a visit; a known one accumulates (idempotent upsert).
- Tracking disabled → `204`, no writes, response tells the page to stop.

## Web analytics

- **Course list** (existing) keeps its summary numbers; each course gets **Open** → `/analytics/courses/:id`, with an **Excel** button for that course. The all-courses export remains.
- **Content tab** — module → activity → resource tree:
  - *Reached* (opened at least once), *Done* (completed), *Typical active time* (median among those who reached it; average on hover), *Dropped here* (last activity in the course was here, course not finished, no activity for 14+ days).
  - Notes by type: text — average scroll %; video — average % watched and most common stopping point; quiz — average score, hardest question (lowest % correct), average seconds per question; PDF/image — opened / downloaded counts; assignment — submitted / approved / waiting.
  - Module and activity rows aggregate their children.
- **Learners tab** — one row per enrolled learner: name, email, progress %, total active / on-screen time, visits, last active, current position (last resource touched), status (completed / on track / stuck / inactive). Sortable; filterable by status.
- **Learner timeline** (click a learner): the module → activity → resource tree with their active / on-screen time, visits, first opened, completed at, quiz score and answers (right/wrong, time per question), video % watched, PDF opened/downloaded.
- **Scope** as today (`analytics.views.scoped_courses`).
- Items whose activity predates tracking show **"not tracked"** for time; completion, scores and dates are still shown.

### API (all scoped like the existing analytics endpoints)

- `GET /api/analytics/courses/<pk>/content/` — the content tree with aggregates.
- `GET /api/analytics/courses/<pk>/learners/` — learner rows with status.
- `GET /api/analytics/courses/<pk>/learners/<user_id>/` — one learner's timeline.
- `GET /api/analytics/courses/<pk>/export/` — the course workbook (the existing all-courses export uses the same builder).

## Excel workbook

One workbook per course; the all-courses export uses the same sheets with course columns.

| Sheet | Row = | Columns |
|---|---|---|
| README | — | definitions: active vs on-screen, median, status rules, "not tracked", UTC |
| Overview (wide) | learner | name; per module: active minutes and % complete; totals |
| Learners | learner | name, email, enrolled at, last active, completed at, progress %, total active / on-screen s, visits, status, current position; subject, teaching level, role at school, country, interface language, competency score; **study participant (consented) yes/no** |
| Modules | learner × module | active / on-screen s, visits, activities done / total, first opened, last seen, completed at |
| Activities | learner × activity | same at activity level, + module title / order |
| Resources | learner × resource | type, required, active / on-screen s, visits, first opened, completed at, quiz score, video % watched, scroll %, PDF opened / downloaded, assignment status |
| Visits (raw) | visit | learner, item path, start, end, active / on-screen s, completed during, language, device, local hour, tz offset, video % this visit |
| Quiz answers | learner × question | quiz, question text, option picked, correct option, right?, seconds on question, answered at |
| Events (raw) | event | learner, resource, type, time, position or from → to |

Conventions: plain seconds in long sheets, minutes in Overview; timestamps in UTC ISO format; ID columns (learner, course, module, activity, resource) and order columns on every sheet. Excel's ~1M-row limit applies to the raw sheets; a CSV download of Visits/Events is a later option if a course ever needs it.

## Privacy

- Privacy Policy gains a short section: what is recorded (time per resource active/on-screen; video, quiz and PDF interactions; interface language, device type, local time of day), why (course improvement, research, learner support), who sees it named (course authors/co-editors, AIDEA partners, admins). No IP address, no precise location, no keystrokes captured by the tracker. Retained like other account data; deleted with the account.
- The export includes all enrolled learners; the Learners sheet marks consented study participants so research analysis can filter. The study team should check whether the consent text needs to mention this data.

## Rollout

- Migration adds the two tables and the switch. Tracking starts at deploy; earlier time shows "not tracked".
- No effect on completion, progress, recommendations or pathways.
- Load: ~2 small requests per minute per actively studying learner.

## Testing

- **Backend:** tracking endpoint (caps, enrolment check, active ≤ on-screen, idempotent accumulation, switch off); aggregates (module/activity sums, medians, drop-off, the four statuses, "not tracked"); learner timeline; each Excel sheet's columns and representative values; scope (a creator sees only their courses).
- **Frontend:** lint, build, locale parity; manual browser check of active vs idle, tab switching, a video (file and YouTube), a quiz, a PDF, and a learner timeline.

## Out of scope

CSV export of raw sheets; real-time dashboards; alerts/notifications to staff about stuck learners (the Learners tab shows status; notifying can come later); tracking outside the activity page (catalogue browsing is already covered by course views).
